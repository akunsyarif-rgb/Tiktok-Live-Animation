# Listener host: always-on Node process (VPS / PC / Codespace)

The listener is independent of Safari, the dashboard and Vercel. If `/control` is closed, the listener keeps working. It needs: **Node ≥ 22**, outbound HTTPS/WSS only, ~150 MB RAM, a clock that is correct (signatures have a ±10 min window: enable NTP).

Status: the procedure below was exercised **without systemd** (clean clone → install → `--check` → replay run → health → SIGTERM, see BUILD_VERIFICATION.md). The systemd unit itself and a real VPS were **not** tested here. TikTok connectivity is **not** tested (unofficial source).

## 1. Install (Ubuntu/Debian example, non-root user `atm`)
```bash
sudo useradd --system --create-home --shell /usr/sbin/nologin atm
# Node >= 22: install from your distro or NodeSource, then:  node -v   (must print v22+)
sudo mkdir -p /opt/atm-live && sudo chown atm:atm /opt/atm-live
sudo -u atm git clone --branch work/atm-live-autonomous https://github.com/akunsyarif-rgb/Tiktok-Live-Animation /opt/atm-live
cd /opt/atm-live
sudo -u atm npm ci --omit=dev --ignore-scripts          # root deps (the listener imports src/lib and @supabase/realtime-js)
sudo -u atm npm --prefix listener ci --omit=dev          # tiktok-live-connector (AGPL-3.0, unofficial)
```

## 2. Configure (secrets stay out of the repo and out of your shell history)
```bash
sudo install -m 600 -o root -g root deploy/listener.env.example /etc/atm-listener.env
sudo nano /etc/atm-listener.env      # fill TIKTOK_USERNAME, SUPABASE_URL, SUPABASE_ANON_KEY, ATM_ROOM, ATM_SIGNING_KEY
```
Where the values come from: `SUPABASE_*` = your dedicated Supabase project (Settings → API: the **anon/publishable** key, never `service_role`); `ATM_ROOM` and `ATM_SIGNING_KEY` = `/control` → Connections / Security (the signing key is shown **once** when you create or rotate keys; lost = rotate and update the overlay URL).

## 3. Validate before the LIVE (no TikTok traffic is generated by `--check`)
```bash
cd /opt/atm-live && set -a && . /etc/atm-listener.env && set +a
node --experimental-strip-types --no-warnings listener/index.ts --check      # exit 0 = config valid + realtime link connected
```
Rehearse the whole chain without TikTok: `ATM_SOURCE=replay ATM_REPLAY_FILE=listener/sample-replay.jsonl node …` (open the overlay; events labelled REPLAY, **not a LIVE**).

## 4. Run as a service
```bash
sudo cp deploy/atm-listener.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now atm-listener
```
| Task | Command |
|---|---|
| status | `systemctl status atm-listener` |
| start / stop / restart | `sudo systemctl start|stop|restart atm-listener` (stop = SIGTERM: flushes pending events up to 4 s, then exits 0) |
| live logs | `journalctl -u atm-listener -f` (lines are redacted: no key, token or room code) |
| health | `curl -s localhost:8787/health` → `{"ok":true,"state":"connected","signed":true,"link":{"ready":true},"sent":…,"undelivered":0,"lastEventAt":…}` (HTTP 200 ok / 503 not ok; loopback only) |
| config re-check | stop service, run step 3, start |
| update | `cd /opt/atm-live && sudo -u atm git pull --ff-only && sudo -u atm npm ci --omit=dev --ignore-scripts && sudo -u atm npm --prefix listener ci --omit=dev && sudo systemctl restart atm-listener` |
| update the TikTok library only | `sudo -u atm npm --prefix listener update tiktok-live-connector && sudo systemctl restart atm-listener` |

## 5. Built-in behaviour (tested)
- Reconnect to TikTok: backoff 5 s → 2 min with jitter; `offline` = streamer not LIVE yet; sign-service rate limits back off 2 min.
- Realtime link: client reconnects by itself; events wait in the outbox (resend until acknowledged; expire 20 s join / 120 s gift). If the link is down for `ATM_LINK_STALL_MS` the process exits **2** and systemd restarts it fresh.
- Crash (`unhandledRejection`/`uncaughtException`) → logs (redacted) and exits 1 → restarted.
- Graceful shutdown on SIGTERM/SIGINT; exit code 0.
- Does not depend on any browser: the only inputs are the env file and the network.

## 6. Diagnosis
| Symptom | Check |
|---|---|
| `--check` fails link | wrong `SUPABASE_URL`/key, project paused (free tier), outbound 443/WSS blocked |
| `/control` shows listener but state `error` | `journalctl`: `SignatureRateLimitError`, TikTok protocol change → update the library, or fall back to replay/simulator |
| state `connected` but no events | streamer not actually LIVE on that username; quiet room (check `lastEventAt`); library drift |
| overlay shows `refused:` counting up | `ATM_SIGNING_KEY` missing/old (after a rotation) or host clock off by > 10 min |
| process restarts every ~5 min | realtime link keeps dropping (network/Supabase) → exit 2 loop |

## 7. Hosting notes
Anything that keeps Node ≥ 22 running works: a small VPS, a spare PC, or a GitHub Codespace (free hours are limited, sleeps when idle: **not** reliable for a LIVE). A phone/iPad cannot host it. Cost: see COST_ESTIMATE.md. Use a dedicated low-privilege user; never run it as root; never expose the health port publicly.
